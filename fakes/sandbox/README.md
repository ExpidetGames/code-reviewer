# fakes/sandbox

The double of the Sandbox platform for the Sandbox-Launcher (#316, #329). It speaks the port of
`dispatcher/src/launchers/sandbox-service.ts` (a VM is created from a snapshot, a command runs in it, a process has a
stdin pipe, a VM is stopped by its name) and matches it structurally: nothing here imports the Dispatcher, because
`fakes/` is shared by every project. The golden snapshot pipeline (#330) has a separate double with a wider port
(builder VMs, snapshots): `fakes/vercel-sandbox/`. The two do not share state.

| File                   | What it is                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `service.ts`           | `FakeSandboxService`, in-process. No command runs. `onExec(label or regular expression, answer)` scripts a command, `exitProcess(vm, code)` ends the Worker's `docker run`, `failNextCreate(error)` makes the platform refuse, `holdNextCreate()` keeps a create pending so a test can abort it. `dropWaits(vm, error)` and `failWaits(times, error)` break the log stream of a running process (a pending or the next `wait()` rejects), `renameCreatedVms(fn)` makes the platform return another name than the requested one. A VM that is stopped ends its processes with 137. For the reaper (#364): `list(filter)` returns the VMs with the name prefix and the tag (`listIgnoresFilter()` makes it return every VM, a platform that does not honour its filter), `seedVm({name, tags, createdAtMs, timeoutMs, status})` puts a VM on the platform that no launch made (a canary, a golden builder, somebody else's), `new FakeSandboxService(now)` stamps creation times from the test's clock, `failNextList(error)`, `failStops(error, name?)` and `healStops()` script the failures. `stdinOf(vm)` is what went through the pipe; `requestText()` is everything else that was sent (create options, command lines, stops), so a test can prove the credential is in the first and not in the second. |
| `local.ts`             | `LocalSandboxService`, the local mode. A "VM" is a temporary directory (the working directory and the home of every command in it). `docker` commands run on this machine with `dockerBin` (the real one, or `bin/fake-docker.sh`); `vm-prepare.sh` succeeds without doing anything; other commands are refused (`127`). Stopping a VM force-removes the containers it started and deletes its directory, so nothing of a job is left for the next. There is no `sudo`, no snapshot and no kernel of its own: it proves the container spec end to end, not the platform.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `bin/docker-worker.sh` | A stand-in `docker` for the hosted end-to-end lane (#332) that runs the REAL Worker where a container would run. It takes the `docker run` the Sandbox-Launcher renders (the real flags, the image id, the entry mode `worker-once` or `probe`), refuses a flag it does not know (125), and starts `E2E_WORKER_COMMAND <mode>` as its own session with the start document on stdin and a closed environment (the `--env` flags, the `E2E_WORKER_PASS_<NAME>` variables, a PATH, a HOME of the "VM"). `E2E_WORKER_GATE` holds a container until the file is gone; `docker rm --force <name>` ends the container's whole tree, also a process in a session of its own; `E2E_WORKER_WRAPPER` runs the entry point in the container's way (the privileged lane: read-only root, the eight capabilities, no-new-privileges, `runner/scripts/dynamic_e2e_worker_container.sh`); `E2E_WORKER_ONCE_UNSET` names what a lane without root takes out of the Worker's environment. Everything it was asked is recorded under `E2E_DOCKER_DIR`. Tests: `dispatcher/src/launchers/docker-worker.integration.test.ts`.                                                                                                                                                                                                      |
| `bin/fake-docker.sh`   | A stand-in `docker` for hosts with no daemon. It records the arguments, the environment and the working directory of a `docker run` and everything written to its stdin, and ends like a Worker would (`FAKE_DOCKER_RUN_SECONDS`, `FAKE_DOCKER_EXIT`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

Rules: dummy values only; no real token, snapshot id or image id. A real platform call from a test is a bug: the
Dispatcher tests replace `@vercel/sandbox` (`src/index.test.ts`) or hand the adapter a stand-in SDK
(`vercel-sandbox.test.ts`).

Used by the hosted end-to-end lane through `dispatcher/src/test-support/hosted-e2e-main.ts` (the Dispatcher as a process, the local mode with `bin/docker-worker.sh`), and by `dispatcher/src/launchers/sandbox.test.ts` (service double), `sandbox-local.integration.test.ts` (local mode with
the stand-in `docker`) and `sandbox-local.privileged.test.ts` (local mode with a real daemon and the real Worker image,
`make test-sandbox-local`).
